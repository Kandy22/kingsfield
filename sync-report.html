Backend changes — /kingsfield/backend/src/
SECURITYmiddleware/auth.ts
MFA enforcement added
Kingsfield's auth.ts was 37 lines — just checked the Bearer token. Mike's is 185 lines and adds:

• enforceLoginMfaIfEnabled() — after every auth check, if the user has mfa_on_login=true in their profile, the request is blocked unless they've completed TOTP at aal2 level.
• requireMfaIfEnrolled() — a second middleware export for routes that specifically need step-up auth (like the MFA enrollment page itself).

Without this, a user who turned on "require MFA on login" could still hit any API endpoint with just their JWT.
NEWlib/safeError.ts
API key redaction in logs
When an LLM call fails, the error message often contains the API key that was rejected (e.g. "Incorrect API key provided: sk-ant-abc123").

This file strips keys matching patterns like sk-ant-*, sk-or-*, AIza*, sk-* before the message hits your logs or gets returned to the client.

Previously those keys could show up raw in server logs.
NEWlib/userApiKeys.ts
Encrypted BYO key storage
Mike moved from storing user API keys as plain text columns (claude_api_key, gemini_api_key) to a separate user_api_keys table where keys are encrypted with AES-GCM before storage.

userSettings.ts was updated to call getStoredUserApiKeys() (decrypt at read time) instead of the old plain columns. Now supports 5 providers: claude, gemini, openai, openrouter, courtlistener.
UPDATEDlib/supabase.ts
Fail-fast on missing env vars
Mike's version throws immediately if SUPABASE_URL or SUPABASE_SECRET_KEY aren't set, instead of silently creating a broken client. Small but catches misconfigured deploys at startup instead of on first request.

What was NOT touched — Kingsfield-only code

These exist only in Kingsfield, not in Mike. They were preserved exactly as-is.

  • AppSidebar — Kingsfield's branded nav with Case Law, Council, Legislation, Analytics, custom theming, and the skull/logo assets. Mike's sidebar only has Assistant, Projects, Tabular, Workflows. Kingsfield's is intentionally more developed for the product.
  • LLM Council backend (backend/src/council/, backend/src/llm-council/) — 5-advisor deliberation system. Orchestrator runs a question through 5 independent advisors (different models/perspectives), they peer-review each other anonymously, a chairman synthesizes a verdict. Unique to Kingsfield.
  • Crew backend (backend/src/crew/) — Multi-agent coordinator. Spawns specialized agents (contract-analyst, researcher, strategist) based on the query, runs them in parallel, coordinates their outputs. Unique to Kingsfield.
  • Hallucination guard middleware (backend/src/middleware/hallucination_guard.ts) — Intercepts responses on guarded routes, scans for citations, runs them through the verification pipeline before the response ships. Core to Kingsfield's anti-hallucination mission.
  • Verification pipeline (backend/src/verification/pipeline.ts) — The 4-gate citation checker. For each cite the LLM produces: (1) does the case exist in CourtListener? (2) is the quote verbatim? (3) does the holding support the claim? (4) is the case in the right jurisdiction? Fails any cite that doesn't pass.
  • Research module (backend/src/research/courtlistener.ts) — Kingsfield's own deep CourtListener integration with citation networks, judge analytics, bulk indexing. More advanced than Mike's courtlistener lib.
  • Case Law, Council, Legislation, Analytics pages — Frontend pages unique to Kingsfield's product. Mike has none of these.
  • Blog — Kingsfield content pages, not in Mike.
